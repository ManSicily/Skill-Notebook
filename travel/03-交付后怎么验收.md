# 交付后怎么验收

> 给不懂技术的人用。每条都是「点一下、看一眼」，不需要你懂代码。
>
> **核心原则：AI 说「做好了」，不要直接信。**让它演示给你看。

## 怎么让 AI 配合你验收

你可以直接说这些话，它听得懂：

- 「你把自动化测试跑一遍，把结果贴给我看」
- 「你用手机视口打开页面，每页截个图给我」
- 「你演示一下点这个按钮会发生什么」
- 「你说做完了，那你说说哪几条你没测到」
- 「你发给我的截图，你自己看过里面的内容吗？」
- 「发布上线之后，你核对了什么？」

**最后一句很重要。**一个诚实的 AI 会告诉你「这几条我没法自己验」；一个不诚实的会跟你说「全部通过」。

---

## 第 1 关：能打开吗

| 让它做什么 | 你应该看到 | 没看到说明 |
|---|---|---|
| 给你一个能打开的链接 | 点开是个页面，不是白屏、不是 404 | 部署没成功，或者路径写错了 |
| 用手机打开 | 页面正常显示，不需要左右拖动才能看全 | 有横向溢出（让它查 `overflow-x`） |
| 看页面标题 | 是你这次行程的名字，不是「双人工作台」这种通用词 | 它可能引用了别的模板没改 |

## 第 2 关：装在手机上

| 让它做什么 | 你应该看到 |
|---|---|
| 教你把页面加到手机主屏 | 主屏出现一个图标，点开是全屏的（没有浏览器地址栏），像 App |
| 装完之后点开 | 正常显示，不是白屏 |

**这一步最常出的问题**：装完之后你改了内容，手机打开还是旧的。

👉 让它检查：所有文件是不是都带了版本号，图标文件带没带。

## 第 3 关：改数据的手感

这是最容易出问题的一关。**一定要在真手机上试，电脑上看不出来。**

| 你亲自做的事 | 应该发生 | 不该发生 |
|---|---|---|
| 在一个输入框里打字 | 页面**不放大**、不左右晃 | 整个页面被放大、能拖动 |
| 点一个行程点的名称 | 那个字**原位**变成输入框 | 弹窗出现在别处 / 下面长出一行 / 输入框被键盘挡住 |
| 改完按回车 | 名字变了，卡片高度几乎没变 | 卡片变高一大截、列表跳位置 |
| 上下滑列表 | 顺滑，不误开任何编辑框 | 滑着滑着进了编辑页 |
| 看一张卡片上有几个能点的地方 | 只有名称、备注、金额 + 右侧几个按钮 | 满卡片都是能点的（说明误触风险高） |
| 长按拖拽手柄 | 卡片浮起来跟手指走，原位留个虚框 | 拖了半天不动 / 松手后列表突然折起来 |
| 把它拖到**别的日期**上松手 | 真的换到那一天了 | 弹回原来那天（跨天没做） |

### 专门试一次「长备注 + 键盘」

**这一步单独拉出来，因为它翻过车** —— 症状是：点开一条长备注，键盘上弹后编辑框被顶上去，手指**下拉一点反应都没有**，上面半截文字永远看不见。

| 你亲自做的事 | 应该发生 | 不该发生 |
|---|---|---|
| 写一条**很长**的备注（十几行），保存 | 卡片正常显示 | —— |
| 点这条备注进入编辑，等键盘弹上来 | 输入框**整个**停在键盘上方，能看见 | 框被顶出屏幕上沿 / 下半截压键盘底下 |
| 在框里**上下拖** | 能拖，能看到第一行也能看到最后一行 | **拖不动**（这就是翻车那次） |
| 键盘收起来 | 页面回到整屏，没有被留出空档 | 底部一直空一块 / 页面来回抽动 |
| 键盘弹着时看底部导航 | 导航在键盘上方，还能点着切页 | 导航被键盘压住点不到 |

**顺带说明为什么"拖不动"要单独试**：有些框是"内容超长但框自己不能滚"（`overflow:hidden`），这种情况下代码去滚动它是有效的、手指拖是无效的 —— 你**肉眼看着以为能滚**，手指一拖才发现纹丝不动。所以这一条不能靠看，必须亲手拖。

### 专门试一次「打包清单」这类要自己增删改的清单

打包清单是"两层结构"（一级分组 → 二级条目），**两级都得能改**，不然你会遇到"想加洗漱用品，却没有地方能新建一个分类"。

| 你亲自做的事 | 应该发生 | 不该发生 |
|---|---|---|
| 在清单最下面点「＋ 新建分组」，建一个「洗漱用品」 | 新分组出现在最下面，里面是空的 | 找不到新建的入口 / 建完不知道去哪了 |
| 点这个新分组的「＋添加」，加一条「牙刷牙膏」 | 条目加进**这一组** | 加进了别的组 |
| 直接点条目文字 | 字原位变成输入框，改完回车就落 | 点不动 / 要开弹窗才能改 |
| 点分组名旁边的 ✎ | 弹出：分组名 + 位置 + 删除 | 点不动（说明分组不能编辑） |
| 改个分组名 | 名字变了，组里条目还在 | 条目丢了 |
| 把这一组挪到第 1 位 | 它排到最前面，里面的条目跟着走 | 条目留在原地 / 顺序没变 |
| 点删除，删掉一个还有内容的组 | 明确告诉你"里面还有 N 条，会一起删" | 悄悄删掉不提示 |
| **把分组全部删光，然后下拉刷新页面** | 还是空的（你的删除说了算） | 原来的分组又自己长回来了 |

**最后那条是重点**：这叫"空就回填种子数据"的毛病 —— 初始化时写的是"如果这个清单是空的，就用默认数据填满"，于是你删光之后一刷新，默认数据全部复活、删除白做。它只在"删光 + 重新加载"这个组合下出现，平时点来点去根本发现不了。

## 第 4 关：数据是不是只有一份

| 你亲自做的事 | 应该发生 | 不该发生 |
|---|---|---|
| 在「住宿」页删掉一晚 | 回到「行程」页，那条也没了 | 住宿页没了、行程里还在（说明存了两份） |
| 在「住宿」页改那一晚的金额 | 行程页那张卡上的金额跟着变 | 两边不一致 |
| 在「费用」页看总额 | 跟行程里各点加起来对得上 | 住宿的钱被算了两遍 |

> 这一关要是没过，说明架构从一开始就错了。**现在就说，别等以后**（做完了再改要动数据，很麻烦）。

### ⚠️ 如果中途撤过字段（比如"价格这栏不要了"），这一关必须多试一步

**只确认"界面上看不到了"是不够的** —— 真正的风险是**老数据被悄悄清空**，而且撤销不回来。

| 你亲自做的事 | 应该发生 | 不该发生 |
|---|---|---|
| 找到一个**老数据里填过这个字段**的点（不是新加的），打开编辑表 | 界面上确实没有那一栏了 | —— |
| **什么都不改，直接点保存** | 保存成功 | —— |
| 保存完之后，再去数据里确认原来那个值 | **原样还在** | 变成空的了 ← 这就是丢数据 |
| 顺着所有页面翻一遍：卡片、详情页、别的页正文、添加弹窗 | 都看不到这个字段了 | 某一处还显示着（说明那个出口漏删了） |

> 为什么必须单独试"原样保存一次"：撤栏只改了界面，**保存回调如果还在给这个字段赋值，用户随便改个别的字段就会触发清空** ——
> 界面正常、测试不报错、当场也看不出问题，等发现时旧值已经没了。

## 第 5 关：离线能用吗

| 让它做什么 / 你做什么 | 你应该看到 |
|---|---|
| 手机上正常打开一次 | 页面加载完 |
| 开飞行模式，再打开（或刷新） | **还能看到行程**，不是「无法连接」 |

## 第 6 关：导航按钮真的能用吗

| 你亲自做的事 | 应该发生 |
|---|---|
| 点任一行程点上的 🧭 | 弹出让你选地图（第一次），或直接打开你手机上的地图 App |
| 打开后的地图 | **目的地已经填好了**，不用你再手动输入 |
| 点一个名字很奇怪的点（比如「机动休整」「睡到自然醒」） | 也能导航 —— 它会用「城市 + 地址」去搜，而不是把这句话原样丢给地图 |
| 点住宿里「住在家里」那种 | **也给导航按钮**（不要有例外） |

**如果点了没反应**：让它检查是不是所有点都给了导航入口。真实反馈里出现过「某一段没有导航按钮」，根因是代码里自作主张加了一条「回家不用导航」的判断。

## 第 7 关：如果做了多人协同

| 让它做什么 / 你做什么 | 你应该看到 | 没看到说明 |
|---|---|---|
| 邀请另一个人加入 | 你发给他一段话术，里面有**链接 + 邀请码 + 要注册** | 只给你一串码（对方不知道怎么用） |
| 对方用手机打开、注册、输码 | 他看到的是**同一份行程**，不是空白 | 邀请码或权限有问题 |
| **你改一个点，然后你自己刷新一次** | **改动还在** | **改动被云端旧数据盖回去了 —— 这是真丢数据，比"看不到变化"严重得多** |
| 把网断掉，改一个点，再刷新 | 改动还在，提示写着「**未同步·已存本机**」 | 改动没了；或者提示只说「同步失败」（让人以为没保存，白重做一遍） |
| 你改一个点，让对方下拉刷新 | 他那边也变了 | 同步没做对 |
| **添加一个新行程点，把所有字段都改一遍（名称、备注、时间、类型都改），再保存** | 保存后**就是你改的那些**，重新打开也还是 | 保存后变回「新行程点 / 空备注 / 默认时间 / 景点」—— 说明保存写到了别的地方去（尤其在多人协同时容易出现） |
| **你打开一个行程点、开始改（先别保存），让它挂一会儿** | 屏幕上**不该冒出任何"已同步"之类的提示**，光标和输入框也不该被弹掉 | 编辑时反复弹同步提示、或输入框突然消失 —— 说明它在"自己跟自己同步"，会把正在改的内容冲掉 |
| 你改一个点保存好，再等半分钟不动 | 安静，不再反复弹同步提示 | 每十来秒弹一次"已同步" |
| 故意输一个错的邀请码 | 明确提示「码不对」，**不是「登录过期」** | 错误文案在瞎猜（这条很重要） |
| 登录失败时 | 有个明确的出口能退回本地模式用 | 被锁在登录页出不来 |

## 第 8 关：它的自测可信吗

**这一关问的都不是功能，是"它说的话能不能信"。**一个功能做得再好、自测不诚实的 AI，你早晚会被它坑一次。

| 让它做什么 | 你应该看到 |
|---|---|
| 把自动化测试跑一遍 | 输出一串「N 条通过、0 条失败」 |
| 问它：「测试里有没有可能一整段没跑，但还显示全绿？」 | 好的做法是**末尾有一条哨兵断言**（检查总共跑了多少条）。没有的话，让它加上 |
| 问它：「你把这些修复关掉，测试会不会红？」 | 它应该真的去试一次（这叫对照实验）。**不肯试的，说明测试不一定抓得住东西** |
| 问它：「**一次只关掉一个修复**，会红几条？」 | 它应该报出一个**很小的数**（比如「红 3 条，正好对应我新加的那 3 条」）。如果说「红 20 条」，说明它一次关了好几处，**红的是哪条对哪处根本说不清**，这个实验等于白做 |
| 问它：「**你发给我的截图，你自己看过里面的内容吗？**」 | 它应该说看过、并能说出图里有什么。如果说「脚本跑绿了所以没看图」，**这就是问题** —— 脚本会绿着给你一张空白图或截错位置的图，不自己看一眼就发给你，等于没验 |
| 问它：「**同一套检查连跑三轮，结果一样吗？**」 | 它应该说一样，并**把三轮结果都贴给你**。如果它说「跑一次就够了」，提醒它：检查脚本自己也可能是"偶发红"，**本机永远绿、线上偶尔红**，只跑一次分不出是应用坏了还是脚本抖了 |
| 问它：「**发布上线之后，你做了哪些核对？**」 | 它应该答得出具体动作：发布前把线上文件拉下来跟本地逐条对过、发布后同一个地址连探多次看版本会不会跳变、并且**用真浏览器打开线上地址把关键路径重跑了一遍**。<br>**如果它只回一句「部署成功」—— 那是文件传上去了，不等于线上是对的**，让它按上面说的重核一遍 |

> **"部署成功"这四个字什么都不能保证。**文件传上去和用户拿到新版之间，隔着缓存、CDN、域名好几道门。
> 所以每次上线都要问一句「你核对了什么」，**没有核对过的上线，等于没上线**。

## 最后：几个信号说明该让它返工

1. **「全部通过」但拿不出证据** —— 让它把原始输出贴出来
2. **你没提过的限制** —— 比如它自作主张「这种地方不需要某功能」，直接让它改回来
3. **改了一处，手机上怎么刷都是旧的** —— 版本号没升，重新发一次
4. **说「部署成功」却答不出上线后核对了什么** —— 传上去了 ≠ 用户拿到了。让它把「拉线上文件对比 + 连探看缓存稳不稳 + 真浏览器跑线上」这三层补上
5. **只跑一次检查就下结论** —— 让它连跑三轮，并且把三轮结果贴出来对比

## 它交东西时应该附带的

- [ ] 能打开的链接
- [ ] 说明文档（有什么功能、数据存哪、怎么备份）
- [ ] 变更记录（改了什么、为什么）
- [ ] 自测结果（哪几条验过、哪几条没验）
- [ ] **改动前后的对照证据**（截图或数据），尤其是"用户报的那个问题"修好没有的证据
- [ ] **上线后核对过什么的记录**（不是一句「部署成功」）
